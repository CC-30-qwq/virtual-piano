# 正式包（Release）发布方案

本文档记录从当前 debug 构建切换到正式签名 release 包所需的全套改动与执行步骤。
适用范围：**内测 / 自己装机分发**（不经应用商店）。

---

## 1. 已确认的决策

| # | 决策项 | 结论 |
|---|---|---|
| D1 | 分发渠道 | 内测 / 自己装机，APK 格式，体积不受商店限制 |
| D2 | 签名密钥库 | 新建一枚正式密钥库（不复用 Cocos 自带 debug keystore） |
| D3 | 音源策略 | 整包内嵌，接受 ~224 MB 体积（不降采样率、不降层数） |
| D4 | 调试面板 | 关闭（`PianoController` 默认值与 `Main.scene` 序列化值同时改 false） |
| D5 | 版本号 | 保持 `versionCode 1` / `versionName "1.0"`，`build.gradle` 不动 |

## 2. 现状与问题

| 项 | 现状 | 是否阻塞出正式包 |
|---|---|---|
| 构建模式 | `build-configs/android.json` 中 `debug: true` | ✅ 阻塞，须改 false |
| 签名 | 走 Cocos 自带 `resources/tools/keystore/debug.keystore`（密码 `123456`） | ✅ 阻塞，debug key 签的包无正式性 |
| 密钥库文件 | 工程内无任何 `.jks` / `.keystore` | ✅ 阻塞，须先生成 |
| 启动场景 | `startScene` = `f3a91c62-…`，与 `Main.scene.meta` 一致 | 正常 |
| 音源包 | `build-bank/` 204 MB，`noCompress += 'flac'` 已配 | 正常（体积即预期） |
| 混淆 | release 默认 `minifyEnabled true` + `shrinkResources true` | ⚠️ 首跑需冒烟验证 |
| 版本号 | `build.gradle` 写死 `versionCode 1` / `versionName "1.0"` | 待定（见 §6-B） |

> 注：当前 debug 包用的是 Cocos 自带的 debug keystore。切换为一枚**新的**正式密钥库后，
> 设备上若已装 debug 包，**必须先卸载**才能安装 release 包（签名不一致无法覆盖安装）。

## 3. 变更清单

### 变更 1：生成正式密钥库

用 JDK 自带 `keytool` 生成，存放于 `build-configs/keystore/virtual-piano-release.jks`。

```bash
"D:/jdk-17.0.20.1+1/bin/keytool.exe" -genkeypair \
  -keystore build-configs/keystore/virtual-piano-release.jks \
  -alias virtualpiano \
  -keyalg RSA -keysize 2048 -validity 10950 \
  -storepass <STORE_PASS> -keypass <KEY_PASS> \
  -dname "CN=Virtual Piano, OU=, O=, L=, ST=, C=CN"
```

- `-validity 10950`（30 年）：避免内测期包过期。
- **Android 发布密钥一经丢失无法找回，也无法用它签署更新包** → 生成后必须异地备份。

### 变更 2：新增正式构建配置

新建 `build-configs/android-release.json`（由 `android.json` 派生，三处改动）：

```json
{
  "platform": "android",
  "debug": false,
  "startScene": "f3a91c62-5d47-4e18-9b02-7c1a4e6d8f30",
  "packages": {
    "android": {
      "packageName": "com.virtualpiano.app",
      "sdkPath": "C:\\Users\\10258\\AppData\\Local\\Android\\Sdk",
      "ndkPath": "C:\\Users\\10258\\AppData\\Local\\Android\\Sdk\\ndk\\28.2.13676358",
      "javaHome": "D:\\jdk-17.0.20.1+1",
      "apiLevel": 36,
      "appABIs": ["arm64-v8a"],
      "orientation": {
        "portrait": false, "upsideDown": false,
        "landscapeLeft": true, "landscapeRight": true
      },
      "useDebugKeystore": false,
      "keystorePath": "D:\\My_Project\\Cocos_Project\\virtual-piano\\build-configs\\keystore\\virtual-piano-release.jks",
      "keystorePassword": "<STORE_PASS>",
      "keystoreAlias": "virtualpiano",
      "keystoreAliasPassword": "<KEY_PASS>"
    }
  }
}
```

> 字段名 `keystorePath` / `keystorePassword` / `keystoreAlias` / `keystoreAliasPassword` 已从
> Cocos 编辑器产物中确认。Cocos 会把它们写成生成的 `gradle.properties` 里的
> `RELEASE_STORE_FILE` / `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD`，
> 供 `native/engine/android/app/build.gradle` 的 `signingConfigs.release` 读取。

#### ⚠️ 坑五：`useDebugKeystore` 默认为 `true`，会静默吃掉你的密钥库

Cocos 3.8.8 的 Android 选项里 `useDebugKeystore` **默认是 `true`**。此时
`keystorePath` 与三个密码字段**全部被忽略**，Cocos 直接写死它自带的
`resources/tools/keystore/debug.keystore`（密码 `123456`）。

**这个失败是静默的** —— 只填 keystore 四项而不关这个开关时：

- 构建全过程**不报任何错**，`build Task (android) Finished` 照常打印；
- 生成的 `gradle.properties` 里 `RELEASE_STORE_FILE` 仍指向 Cocos 自带的 debug keystore；
- 最终 APK 能正常打包、正常安装、正常跑，**只是用 debug key 签的** —— 到上架或
  做覆盖升级时才会暴露。

编辑器 UI 里这个联动是可见的，可以此推断因果：

```html
<ui-file path="keystorePath" :disabled="pkgOptions.useDebugKeystore">
```

开关为真时 keystore 路径输入框是禁用状态。

**所以 `"useDebugKeystore": false` 是必填项，不是可选项。** 并在构建后按 V0 复核。

### 变更 3：敏感信息隔离（必须）

Cocos 的 `configPath` 机制**不支持**从环境变量读密码，明文写文件是唯一路径。
因此：

- `.gitignore` 追加：
  ```
  build-configs/android-release.json
  build-configs/keystore/
  ```
- 提交一份 `build-configs/android-release.example.json`（占位密码），供换机器时参考。

### 变更 4：版本号（保持不动）

`native/engine/android/app/build.gradle` 中：

```groovy
versionCode 1
versionName "1.0"
```

已确认维持 `1` / `"1.0"`，`build.gradle` 本次不动。后续每次对外发版必须递增
`versionCode`，否则无法覆盖安装。

### 变更 5：调试面板（已关闭）

`PianoController.ts` 的 `showDebugHud` 默认值与 `Main.scene` 的序列化值均已改为 `false`。

> 坑点：**场景里的序列化值优先级高于 TS 默认值**。只改 TS 默认值，编辑器里的组件
> 仍会按场景中存档的 `true` 渲染出读数 —— 两处必须同时改。
>
> 内测需要看读数时，在编辑器里勾选组件的「是否显示调试读数」即可，不必改代码，
> 但勾选后别提交 `Main.scene`。

## 4. 执行步骤

```bash
cd D:/My_Project/Cocos_Project/virtual-piano
export JAVA_HOME="D:/jdk-17.0.20.1+1"
export PATH="$JAVA_HOME/bin:$PATH"

# 第一步：Cocos 构建（生成 build/android/proj 与 release 变体的 native 工程）
env -u ELECTRON_RUN_AS_NODE "D:/Cocos/editors/Creator/3.8.8/CocosCreator.exe" \
    --project "D:/My_Project/Cocos_Project/virtual-piano" \
    --build "configPath=D:/My_Project/Cocos_Project/virtual-piano/build-configs/android-release.json"
# 成功标志：build Task (android) Finished in (Ns)
# 结尾的 Electron 缓存报错与非零退出码是编辑器退出噪声，非构建失败（见《构建环境与命令行构建》§2.4）

# 第二步：编译原生 release 变体
cd build/android/proj
export ANDROID_HOME="C:/Users/10258/AppData/Local/Android/Sdk"
./gradlew assembleRelease
```

**预期产物**：`build/android/proj/build/virtual-piano/outputs/apk/release/virtual-piano-release.apk`
（release 为 isDefault 变体，路径与文件名以实际输出为准，`assembleRelease` 的日志末尾会打印）。

**预期耗时**：release 是全新构建变体，native 侧（cocos.so + 自研 `piano` 引擎）会全量重编译，
首次明显长于 debug 的增量构建。

## 5. 验证清单

按顺序逐条验证，**任一条不过则不得分发**。

| # | 验证项 | 命令 / 方法 | 通过标准 |
|---|---|---|---|
| V0 | 签名配置已注入 | 构建后 `grep RELEASE_ build/android/proj/gradle.properties` | `RELEASE_STORE_FILE` 指向本工程的 `.jks`，**不是** Cocos 的 `tools/keystore/debug.keystore`（见坑五） |
| V1 | 签名者非 debug key | `apksigner verify --print-certs <apk>` | 证书 DN 为 `CN=Virtual Piano`，非 `CN=Android Debug` |
| V2 | 版本与 API 级别 | `aapt2 dump badging <apk>` | `versionCode='1'`、`minSdkVersion='26'`、`native-code: 'arm64-v8a'` |
| V3 | 自研 C++ 引擎已编入 | release 下**不能**查 build tag（见 §5.1），改查桥接方法名 | `jsbPiano` / `loadBank` / `submitEvents` 等均能在 `libcocos.so` 中搜到 |
| V4 | 音源包已随包 | `unzip -l <apk> \| grep -c "assets/.*\.flac"` | 与 `build-bank/` 中 flac 数量一致 |
| V5 | 装机运行 | `adb install -r <apk>` 后手动演奏 | 有声音、无崩溃、多点触控与滑奏正常 |
| V6 | 冷启动耗时 | 设备上实测 | 与 debug 包同量级，无退化（参照《音源冷启动载入耗时定位与优化方案》的基线） |
| V7 | 混淆未误伤 | 观察 Release 版运行日志 | 无 `ClassNotFoundException` / `NoSuchMethodError` |

> V7 若失败：临时在 `build.gradle` 的 `release` 块把 `minifyEnabled` 置 false 复测以定位，
> 定位后须补 proguard keep 规则并**恢复** `true`，不要带着关闭状态发布。

### 5.1 关于 V3：release 下不能查 build tag

`piano_engine_build_tag()`（`PianoEngine.cpp:495`）返回 `piano-engine-m0-skeleton`，
是个**零调用者**的诊断函数。release 走 `-DHIDE_SYMBOLS=ON` + `--gc-sections`，
该函数连同字符串常量一起被回收，`tag_count` 必然为 **0** ——
**这不代表自研引擎没编进去。**

《构建环境与命令行构建》§3 那条「查 tag」的判定方法成文于 M0-1 验收（debug 构建），
**对 release 不适用**。实测对照（同一份代码）：

| 构建 | `piano-engine-m0-skeleton` | `jsbPiano` | `loadBank` |
|---|---|---|---|
| debug | 1 | 1 | 5 |
| release | **0** | 1 | 3 |

（release 计数偏少是字符串池合并，不是缺失。）

release 下应改查桥接入口 —— 它们经 `Game.cpp:58` 的
`addRegisterCallback(piano::jsb_register_piano)` 强引用，不会被 GC：

```bash
python -c "
d = open('.../stripped_native_libs/release/stripReleaseDebugSymbols/out/lib/arm64-v8a/libcocos.so','rb').read()
for n in [b'jsbPiano', b'loadBank', b'submitEvents', b'getActiveVoices']:
    print(n.decode(), d.count(n))
"
```

这些若也为 0，才说明真的没编进去，回到《构建环境与命令行构建》§3 排查 CMake。

## 6. 密钥库备忘

- 文件：`build-configs/keystore/virtual-piano-release.jks`
- 别名：`virtualpiano`
- 算法 / 位数：RSA 2048，有效期 10950 天（30 年）
- 证书主体：`CN=Virtual Piano, OU=VirtualPiano, O=VirtualPiano, L=Unknown, ST=Unknown, C=CN`
- 密码：写入 `build-configs/keystore/.storepass`，已 gitignore

> **密码不记入本文件** —— `docs/` 是入库目录，密码只能留在 gitignored 的 `.storepass` 与
> 你的密码管理器里。

⚠️ **务必异地备份**：Android 发布密钥不可找回，也无法用它重签更新包。请把 `.jks`
与密码一并备份到 U 盘或密码管理器。这枚密钥同时用于后续所有内测包的覆盖升级，
一旦丢失，用户必须卸载重装。

## 7. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 密钥库丢失 | Android 发布密钥不可找回，丢失后无法发布更新 | 生成后立即异地备份（U 盘 / 密码管理器） |
| 密码入库 | `configPath` 强制明文密码 | 变更 3 的 `.gitignore`，且提交前 `git status` 复核 |
| 签名不兼容 | 设备上已有 debug 包，签名不同无法覆盖安装 | 安装前先 `adb uninstall com.virtualpiano.app` |
| 首跑 release 全量编译 | native 全量重编译，耗时长 | 留足时间；失败时先看 CMake 是否收到 `PianoEngine.cpp.o` |
| 混淆误伤 JNI | release 开启 minify + shrinkResources | 验证 V7；必要时补 keep 规则 |
| 体积 224 MB | 内测自装可接受，但传输/安装偏慢 | 本次按 D3 接受，不处理 |
